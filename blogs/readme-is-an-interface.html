Your README is the front door. Please install a handle.

Prasiddha Mainali · November 1, 2026 · 1 min read

HELLO,
READER.THE CURIOSITY LOG / PRASIDDHA MAINALI

A repository is an invitation. Its README is the first conversation with a person who does not know what you already know.

That person might be a collaborator, a reviewer, or you returning after two months. All three deserve better than “run the code.”

Start with the thing, not the stack

“A Python project using several libraries” describes a crowded neighborhood. It does not identify the house.

Begin with what the project does and who might find it useful. A concrete example beats a paragraph of superlatives. If it is an experiment rather than a finished tool, say so. That is context, not an apology.

Give the reader one successful path

Choose a small example. Explain the input, the command, and the expected kind of output. Mention anything the reader must supply themselves. Do not hide a required dataset halfway down a notebook.

Keep this path short enough to test after a change. Instructions that were once correct can become an accidental puzzle when files move.

Show where the project ends

A limitations section is useful because it makes the boundary visible. Which parts are exploratory? What has not been evaluated? Which tasks are outside the scope?

There is no need to turn the README into a defensive essay. A few specific sentences help a reader decide whether the project fits their needs.

Leave a map for your future self

Explain the main folders, where results belong, and how to reproduce the basic example. Link to longer notes rather than putting every detail on the front page.

Good documentation makes curiosity easier to act on.

The repository can still have personality. Add a diagram, a clear screenshot, or a joke. Just make sure the joke is not that nobody can find the entry point.
