Build smaller. Learn something before dinner.

Prasiddha Mainali · November 1, 2026 · 1 min read

ONE
QUESTION.THE CURIOSITY LOG / PRASIDDHA MAINALI

It is easy to start with a small idea and end with a system diagram that includes a mobile app, an autonomous agent, three dashboards, and a funding strategy.

Ambition is useful. But a learning project needs a way to tell whether anything has actually been learned.

Give the experiment one question

Instead of “build an intelligent platform,” try “what happens when I change this one part?” The question should be small enough that the answer can be written in a paragraph.

A narrow experiment is not a declaration that the larger problem is unimportant. It is a way to approach it without confusing activity with understanding.

Decide what you will keep

Before starting, choose an artifact: a plot with an explanation, a tiny working example, a comparison table, or a note describing a failure. This gives the session somewhere to land.

A folder full of half-finished notebooks may contain real effort. A clear note makes that effort easier to build on.

Separate observation from explanation

“The result changed” is an observation. “It changed because of this particular mechanism” is a stronger claim. Keep those sentences separate until the experiment supports connecting them.

This habit makes disappointing outcomes more useful. A result that contradicts your expectation can still tell you which question to ask next.

End with a next step, not a new universe

Write down what surprised you, what you would repeat, and the smallest follow-up that might clarify the result. Then stop expanding the scope.

One answered question is a better foundation than six impressive project names.

The big project will still be there tomorrow. With a few small experiments behind you, it may even be easier to explain why it should exist.
